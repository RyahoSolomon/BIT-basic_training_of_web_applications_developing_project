# 回合推进与单位显示

[turn-flow.js](../game/battle/scripts/turn-flow.js) 管理行动开始、电脑确认和下一单位的等待。[control.js](../game/battle/scripts/control.js) 保留整轮效果与关卡事件，[ai.js](../game/battle/scripts/ai.js) 执行一次电脑动作，[units-update.js](../game/battle/scripts/units-update.js) 刷新单位的显示。移动、伤害和胜负规则仍使用各自的规则模块。

## 行动阶段

`battle_turn_flow` 保存当前行动编号、单位对象、阶段和等待任务。正常流程如下：

| 阶段 | 允许的操作与后续流程 |
| --- | --- |
| `ready` | 为当前存活单位开始新行动 |
| `player` | 玩家移动或使用操作；移动不结束行动，其余操作按原规则结束 |
| `computer` → `acting` | 电脑选择并执行一次动作，包括原地等待 |
| `confirmation` | 保留电脑行动标记，等待玩家确认 |
| `waiting` | 移除战斗操作入口，约 300 毫秒后选择下一位存活单位 |
| `ended` | 终局已接管，不再开始行动或安排等待 |

`start_turn()` 不会重复启动同一行动，因此不会重置玩家已移动的状态，也不会重复电脑伤害。电脑确认按钮绑定创建时的行动编号；确认只能消费当前电脑行动，旧按钮无法确认后续行动。等待期间的重复结束请求也不会增加新的推进任务。

行动间隔使用 `setTimeout`，期间浏览器可以处理绘制、其他计时器和点击，不再同步循环等待。等待任务同时核对行动和任务编号；终局或离开页面会取消它，即使旧回调随后触发也无效。浏览器从页面缓存恢复时，只重新安排尚未完成的等待，不重放已执行的电脑动作。

等待结束后，按原数组顺序跳过死者。跨过数组末尾时执行 `end_round()`，仍按原顺序处理护甲恢复、持续效果、机关与关卡事件；终局检查通过后才开始下一单位。胜负与成就确认的具体流程见 [胜负与通关结算](battle-settlement.md)。

## 单位显示

`units_display_update()` 使用 `Map` 按 `Unit` 对象关联显示节点，不依赖召唤单位可能缺失的 `uuid`。同一存活单位的图片、生命与护甲文字、等级经验以及状态标记在刷新和移动时继续使用原节点。

- 新单位首次显示时创建节点；死亡或被新对象替换时移除旧节点。
- 位置变化时更新原节点的坐标，数值变化时更新对应文字；未变的文字也保留其文字节点。
- 举盾、流血、中毒和强化标记通过隐藏、显示复用，清除状态再恢复也不会重建。
- 地形与单位提示同步更新；移动后原格子不再显示该单位的信息。

显示节点继续使用原来的 ID、图片、类名、偏移量和文案。初始化与召唤仍按原方式安排单位，渲染不改变战斗数据、行动次数或伤害结算。

## 验证

运行 `npm run test:turn`，或随 `npm test` 一并运行：

- [回合回归](../scripts/smoke-turn-flow.cjs) 检查异步等待期间的响应、电脑确认、重复请求、旧回调以及终局和页面离开时的取消。
- [显示回归](../scripts/smoke-unit-rendering.cjs) 遍历六张实际地图的 55 个存活单位，验证节点身份、原有布局和文字，并检查实际移动、状态切换、死亡、无 `uuid` 召唤与对象替换。
